# What verification proves

Run `python3 tools/demo.py verify` from the repository root. The runner imports assets in the chosen Godot, runs the scene headlessly and writes `verification/structural_validation.json`. A failed required check causes a nonzero exit code.

The six runs are 20, 50, 80 and 120 km/h with the declared full-width symmetry boundary, followed by unweakened/weak-rail 80 km/h runs with symmetry released. The latter pair compares material strength under identical boundary conditions.

Required checks cover:

- Finite point positions and velocities.
- Analytic wall/floor contact clearance.
- No large kinetic-energy explosion, with a small allowance for gravity/numerics.
- Total mass accounted once at 1,210 kg.
- Permanent rest-length change and yielding connections.
- Increased cabin shortening in selected higher-speed cases.
- Actual Godot bone-anchor positions and normalised vertex weights.
- A changed physical result when one rail's yield strength changes.
- Replay return to pristine state and restoration of the final inspected state.
- Reset of connection rest lengths and node damage.

The shortening metrics use Euclidean distances between structural section centres. They do not treat a car's yaw as front shortening. Roof span is measured relative to section geometry rather than global height alone.

`verification/handover_validation.json` records the fresh six-run check performed while creating this repository. The optional model construction was also rebuilt successfully in a temporary copy with Blender 4.5.9 LTS, producing 32,947 LOD0 and 16,123 LOD1 triangles before runtime refinement. All seven cabin-fit tests passed.

`verification/baseline.json` is an immutable copied reference from the validated source snapshot. `structural_validation.json` is generated by the current checkout and ignored by Git. Compare behaviour and pass/fail; timing and tiny floating-point differences can vary between machines. The baseline report includes the original engine/build identity.

`python3 tools/demo.py check` independently checks package integrity, deterministic graph regeneration, mass and endpoint sanity, GLB mesh names and file checksums. It does not run physical simulation.

## Visual review

Use the plain mesh with local folds disabled to judge the structural skin alone, then enable the detail shader and compare. Check the textured and ghost views from front, side and top; scrub before impact, peak collapse and the held end state. Screenshots in `docs/images/` are genuine rendered output from the included structural snapshot.

The final shape can include intersecting panels because this baseline has no structural or panel self-contact. Passing automated checks does not certify lifelike folds, safe occupant space, a correct energy budget or real Niva crash performance. Review the shape as well as the numbers.

## Timing scope

`mean_step_us` and `max_step_us` measure this GDScript structural step. Skin-build and visual-upload fields measure their named operations. None is a complete frame-time/GPU/multiple-car benchmark. The solver only runs while an impact is active. A production adaptation should profile its target hardware and port the hot solver if required.
